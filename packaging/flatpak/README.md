# NearShare Flatpak

`dev.dhivalabs.nearshare.yml` packages the same installed tree as the `.rpm`
and the Arch package: `.github/workflows/ci.yml` builds it from the `.deb`
with `packaging/linux-distros/build-tree.sh` (the `.deb`'s files, with the
protobuf bindings regenerated for a bundled pure-Python protobuf), unpacks it
into `tree/` (gitignored) and runs flatpak-builder in the
`ghcr.io/flathub-infra/flatpak-github-actions:gnome-51` container on x86_64
and aarch64. The GNOME 51 runtime provides Python, PyGObject, GTK4 and
libadwaita; zeroconf and cryptography (with ifaddr, cffi and pycparser) are
installed offline from pinned PyPI wheels listed in the manifest. CI then
installs the bundle on the Ubuntu runner with the runtime from Flathub and
runs `test-bundle.sh`: ldd inside the sandbox, the protocol tests and
`tools/gui-smoke.py`.

Install a bundle (the GNOME runtime comes from Flathub):

```bash
flatpak remote-add --if-not-exists --user flathub https://dl.flathub.org/repo/flathub.flatpakrepo
flatpak install --user ./nearshare-<version>-x86_64.flatpak
flatpak run dev.dhivalabs.nearshare
```

## Permissions, and what the sandbox leaves out

- `--share=network`: mDNS discovery (python-zeroconf's own multicast
  sockets; Avahi is not involved) and the transfer connections.
- `--system-talk-name=org.bluez`: the BLE trigger advertisement through
  BlueZ's D-Bus API. No raw Bluetooth sockets are used, so `--allow=bluetooth`
  is not needed.
- `--filesystem=xdg-download`: received files go to `~/Downloads`. Files to
  send are picked with the file chooser portal.
- Not in the Flatpak: **Direct mode** (it runs the host's `nmcli`, which the
  sandbox cannot reach; the app reports it as unavailable), the
  **Nautilus "Send with NearShare"** menu item and the send/toggle desktop
  entries (they drive the app from outside the sandbox), and `nearshare
  install` (desktop integration is the Flatpak's own). Use the `.deb`,
  `.rpm`, Arch package or snap for those.

## A Flathub submission would differ

- Replace the `tree` directory source with the release source archive and
  build the app tree in the manifest: install `nearshare/` and the launcher,
  and generate the protobuf bindings with a `grpcio-tools` module (or ship the
  generated files in the archive).
- Flathub prefers the PyPI sources generated by `flatpak-pip-generator`; the
  wheel list here has the same shape and can be regenerated with it.
- Screenshots in the metainfo and app id verification for `dhivalabs.dev`.
